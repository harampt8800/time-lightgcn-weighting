# H3 교란요인 — 임베딩 크기 붕괴

**요약:** mul의 오버스무딩 완화 주장은 대조군 없이는 성립하지 않습니다.

---

## 문제

`mul`은 매 layer마다 α(Δt) < 1을 곱합니다. K번 반복하면 깊은 layer의 임베딩 크기가
지수적으로 줄어듭니다.

소형 이분 그래프(유저 40, 아이템 60, 엣지 300, d=16, λ=0.01)에서 측정한
레이어별 임베딩 L2 norm:

| layer | vanilla | mul | constc (c=ᾱ=0.225) |
|---:|---:|---:|---:|
| 0 | 4.0019 | 4.0019 | 4.0019 |
| 1 | 1.6103 | 0.4603 | 0.3625 |
| 2 | 1.0045 | 0.0885 | 0.0509 |
| 3 | 0.7666 | 0.0193 | 0.0087 |
| 4 | 0.6700 | **0.0045** | 0.0017 |

layer 4의 기여가 바닐라 대비 **1/150**입니다. 사실상 존재하지 않습니다.

---

## 왜 치명적인가

레이어 결합이 `e = Σ_k α_k · e^(k)` (α_k = 1/(K+1) 균등)이므로, 깊은 layer의 크기가
0에 수렴하면 **K=5 모델이 실질적으로 K=2~3 모델처럼 동작**합니다.

따라서 "K=5까지 성능이 유지된다"는 H3의 예측 결과가 나와도, 그것이

- (A) 시간 가중이 집계를 비균일하게 만들어 오버스무딩을 완화했기 때문인지
- (B) 단지 깊은 layer를 죽여서 오버스무딩이 발생할 여지가 없어졌기 때문인지

구별할 수 없습니다. (B)라면 이건 시간 정보와 무관하며, α_k를 c^k로 바꾼 것과
동일합니다. 발표에서 이 질문 하나로 H3가 무너집니다.

---

## 대조군 두 종

### 1. `--mode constc --const_c <ᾱ>`

시간과 무관한 상수를 모든 엣지에 동일하게 곱합니다. 크기 축소 효과는 mul과 같지만
비균일성은 없습니다.

- constc도 K=5까지 버팀 → 원인은 크기 축소. **H3 기각**
- mul만 버팀 → 비균일성이 진짜 원인. **H3 지지**

`ᾱ`는 mul에서 학습된 α의 평균값(`alpha_mean` 로그 컬럼)을 사용합니다.

### 2. `--mode mul --alpha_renorm`

α를 목적지 노드별 평균이 1이 되도록 재정규화합니다.

```
α'_e = α_e / mean_{e' → dst(e)} α_{e'}
```

총 유입 크기는 보존되고 **엣지 간 상대적 비균일성만** 남습니다. 크기 축소 경로를
원천 차단한 상태에서 H3의 메커니즘 주장을 직접 검증합니다.

이 조건에서도 오버스무딩이 완화되면 (B) 해석이 완전히 배제되어 H3가
반박하기 어려워집니다. **가장 강한 형태의 증거입니다.**

---

## 실행

```bash
# 1) mul 을 먼저 돌려 학습된 alpha_mean 확인
python src/train.py --data data/gowalla --mode mul --K 5 --seed 0
python -c "import json;print(json.load(open('runs/gowalla_mul_K5_s0_final.json'))['alpha_mean'])"

# 2) 그 값을 c 로 넣어 대조군 실행
python src/train.py --data data/gowalla --mode constc --const_c <위 값> --K 5 --seed 0

# 3) 재정규화판
python src/train.py --data data/gowalla --mode mul --alpha_renorm --K 5 --seed 0
```

실험 2~3회 추가로 H3의 설득력이 완전히 달라집니다.
